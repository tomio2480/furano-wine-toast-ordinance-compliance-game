## 🧪 空振りのテストは変異で見つける

レビューで，対応するコードを消しても通るテストが 2 本見つかった．
どちらも，実装の一部を外した変異体で確かめた．

- 時間切れ後の命中を無効にするテストは，60 秒の時点に参加者が残っていなかった．
  標的が無く，時間切れの判定と無関係に同じ状態を返していた
- 同時表示の上限を見るテストは，使ったシードで上限に一度も達していなかった．
  上限の判定を常に偽にしても，結果は変わらなかった

直し方は，前提が成り立つことを先に assert する形である．
時間切れの直前に参加者を出し，1 人いると確かめてから雪玉を投げる．
上限のほうは参加者を上限まで置き，出現の見送りを直接確かめる．
以後の修正でも，足したテストの多くは，実装を戻した状態で落ちるか確かめた．

## 🔁 予定で回るループは予定を必ず進める

`advance` は，次の出来事の時刻が目標に届くまで処理を繰り返す．
次の時刻は，出現の予定と退場の予定のうち早いほうである．

レビューで，時間切れちょうどに参加者の現れる不具合が見つかった．
最初の修正では，時間切れなら出現の処理ごと飛ばした．
すると出現の予定は 60 秒のまま残り，`advance` が止まらなくなった．
テストが返らなくなったことで気づいた．

修正後は，予定だけ進めて参加者を出さない．
時間切れの判定を `spawn` の中へ移し，混雑や空き枠なしと同じ扱いにした．
予定の時刻に沿って回るループは，見送る分岐でもカーソルを進める必要がある．

## ⌨️ 焦点の区別に :focus-visible は使えない

乾杯は Space で操作する．消音ボタンに焦点があると，Space はそのボタンへ譲られる．
消音をポインタで押した後も焦点は残る．このため次の Space は乾杯にならない．
レビューでこの点を指摘された．

最初の案は，`:focus-visible` の有無により焦点の移り方を見分けるものだった．
Chrome は，キーが押された時点で焦点を `:focus-visible` の状態へ切り替える．
ポインタで移した焦点も例外ではない．
このため Space の keydown を受けた時点では，移り方を区別できなかった．

採った方法は，ポインタで押した直後に焦点を乾杯ボタンへ戻すことである．
`click` の `event.detail` は，ポインタによる押下なら 1 以上，キーボードなら 0 になる．
押し方はこの値で見分ける．焦点を戻すのはカウントダウン中とプレイ中だけである．
Tab で消音へ移り，Space を押す操作は従来どおり使える．

## 🔀 積み重ねた PR を squash でマージする

PR は M1 を先頭に親子で積み重ねた．
親を squash で main へ入れ，続いて子に移った．
squash の後，子のブランチには親の元のコミットが残る．
このため main を子へマージすると，同じファイルの追加どうしが add/add で衝突する．

子のブランチは，親の内容をすべて含んだうえで先へ進んでいる．
そこで衝突は子の側（`git checkout --ours`）で解いた．
解いた後は `git diff --cached --stat origin/<子のブランチ>` が空であることを確かめた．
main が親の内容しか持たない場合，正しい結果はマージ前の子の木と一致する．

もう 1 つは順序である．親のマージより前に，子の PR の base を main へ変えた．
マージ用の補助スクリプトは，マージと同時に親のブランチを消す．
base のブランチが消えた後の子の PR の扱いを，GitHub の自動処理に委ねないためである．

## 🤖 auto-merge はブランチを消さない

PR #14 は auto-merge でマージした．
リポジトリの `delete_branch_on_merge` は無効であり，マージ後もブランチが残った．
auto-merge によるマージの後は，ブランチを手で消す．

## 🚀 公開ワークフローの concurrency

Pages の公開ワークフローで，concurrency を deploy ジョブだけへ移す案を試した．
セキュリティの検査で，古い版が新しい版の後に公開されうると指摘された．

build は並行して走るため，古い実行の build が遅れて終わる場合がある．
すると古い実行の deploy は，新しい実行の deploy より後に動く．
ワークフロー単位の concurrency なら，実行全体が到着した順に並ぶ．
そこで concurrency はワークフロー単位に戻し，group を `pages-${{ github.ref }}` とした．

## 📦 lock ファイルは CI と同じ npm で作る

手元の npm 11.6.1 が作った lock に対し，CI の `npm ci` は失敗した．
lock に `@emnapi/core` と `@emnapi/runtime`（2.0.0-beta.2）が無いためである．
CI の Node 26.13.1 には npm 11.20.0 が付く．手元は同じ Node で npm 11.6.1 だった．
`npx npm@11.20.0` で lock を作り直すと 2 つが入り，`npm ci` も通った．
以後，lock を変えるときは npm 11.20 以上を使う．

## 🛡 CodeQL の既定のセットアップ

リポジトリには CodeQL の高度な設定（`codeql.yml`）を置いた．
しかし既定のセットアップも有効だったため，解析が失敗した．
エラーの文面は，既定のセットアップと高度な設定を併用できない趣旨だった．
利用者の了承のもと，API で既定のセットアップを無効にした．
