## 🔠 大きな画面の文字は rem に倍率を掛ける

大きな画面では，舞台に比べて文字が小さく見えた．
利用者の選んだ方針は「舞台に合わせ，最大 1.5 倍まで大きくする」である．

最初の案は `clamp(1rem, 舞台幅に比例, 1.5rem)` だった．
この形では，利用者が文字の設定を 2 倍にしても，画面の文字が 2 倍にならない．
幅 412px の舞台では 1.77 倍にとどまる．比例の項が rem に追従しないためである．

採用した形は「1rem × 倍率」である．

- 倍率は舞台の幅から JavaScript で求め，`--text-boost` として `#stage` に置く
- 幅 430px までは 1 倍とし，645px 以上では 1.5 倍とする
- `#stage` の文字を `1rem × 倍率` とし，子の要素は em で決める
- 倍率は文字の設定と無関係のため，設定を 2 倍にすれば画面の文字も 2 倍になる

表 1. 検討した形と採らなかった理由．

| 形 | 採らなかった理由 |
|---|---|
| `clamp(1rem, 比例, 1.5rem)` | 文字の設定を 2 倍にしても，大きな画面では 2 倍にならない |
| 長さを長さで割る CSS の計算 | 対応するブラウザが限られる |
| コンテナクエリで段階的に倍率を変える | 倍率が段になる．コンテナ自身の文字は指定できない |

実装で確かめたことを残す．

- `element.style.setProperty` は CSSOM の操作のため，`style-src 'self'` の CSP でも動く
- 未登録のカスタムプロパティでは，`cqw` と `em` は値を使う要素で解決される

## 📱 横向きでは帯と乾杯ボタンを舞台の外へ出す

9:16 の舞台は，高さ 360px の横向きの画面では幅 202px になる．
文字を 2 倍にすると，上部の帯と乾杯ボタンで参加者がほぼ隠れた．
一方，舞台の左右には広い余白が残る．

そこで横向きのスマートフォンでは，帯を左の余白へ，乾杯ボタンを右の余白へ出した．

- 条件は，横向き，高さ 540px 以下，縦横比 3 / 2 以上とした（`style.css` の末尾）
- 余白の幅は `calc((100vw - 100cqw) / 2)` で求める．舞台は中央に置いている
- 縦向きと PC の配置は変えない

帯の文字を減らす案や，数値の強調を弱める案も考えた．
しかし 32px の文字では，幅 200px に帯とボタンを並べきれない．

## 🎯 当たり判定は絵の外形から作る

当たり判定は，人の絵の中心から左右対称に置いていた．
絵は右手に飲み物を持つため右へ広く，ニット帽の飾りの分だけ上へ高い．

- 外形を `FIGURE`（左 −30，右 44，上 −157，倍率 1）として，描画から求めた
- 最小の幅は論理座標で 80 とし，舞台の幅 200 CSS px で 44 CSS px を保つ
- 奥の列は，テーブルに隠れた足もとを除いて天板の上端までとする
- テストは論理座標でなく，最も狭い舞台での CSS px で書く

外形の値は絵と別に持つため，絵を変えたら値も合わせる必要がある．
確かめるときは，開発サーバーで当たり判定の枠を一時的に重ねて描いた．

## 🌙 会場の絵は写真で確かめる

帯の塗りを，残り時間と得点の項目ごとの下地に替えたことがある．
文字を大きくしたとき，帯が参加者を隠す範囲を狭めるためだった．
ところが天井が明るく見え，暗い天井の会場から遠ざかった．
利用者の写真を受けて，暗い帯を戻した．

椅子も，要件書の表 9 の言葉から「濃茶の曲木風」として描いていた．
写真の椅子は，明るい木の肘掛け椅子で，座面は丸い緑である．
写真に合わせて描き直し，表 9 も改めた．

要件書の言葉だけで絵を決めず，写真があれば早めに照らす．

## 🧪 検査で踏んだ点

- E2E で URL から正規表現を作ると，CodeQL の `js/incomplete-hostname-regexp` に当たる
  - テストのコードでも high として扱われ，PR のチェックが落ちる
  - URL は正規表現にせず，文字列として比べる
- 「焦点を移した後に読み上げる」という順番は，MutationObserver では確かめられない
  - コールバックはマイクロタスクとして遅れて走るため，焦点を移した後に記録される
  - `focusin` の中でライブリージョンの文を読み，焦点を移した瞬間の値を残す
- 修正の後に書いたテストも，修正前の実装に戻して落ちるか確かめた
  - CSS は，元の `style.css` と `index.html` に戻して確かめた
  - 当たり判定は，元の値に新しい定数だけを足して確かめた
