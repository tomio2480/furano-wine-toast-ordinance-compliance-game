# 🍷 furano-wine-toast-ordinance-compliance-game

## 📝 要約

富良野市の乾杯条例を題材にしたブラウザゲーム「乾杯条例ガーディアン」のリポジトリである．
スマートフォンと PC のブラウザで遊べ，GitHub Pages で公開する．
ランキングなしの版（M1〜M4）を実装した．ランキング（M5 以降）はまだない．

## 🎮 ゲームの概要

- 舞台は冬の富良野で開く室内の懇親会である
- 会場はコンシェルジュ フラノ 1 階の広間をモチーフにする
- ふらのワインとふらのぶどう果汁以外を持つ参加者に雪玉を当てる
- 全員が適合飲料を持つ間は，乾杯ボタンの長押しで得点を伸ばす
- 得点は SNS に共有できる．ランキングは今後 Google ログインで登録できるようにする

公開予定の URL は次のとおりである．

```text
https://tomio2480.github.io/furano-wine-toast-ordinance-compliance-game/
```

## 🕹 遊び方

制限時間は 60 秒である．表 1 は得点の増減である．

表 1. 得点の増減．

| 事象 | 得点 |
|---|---|
| ふらのワインとふらのぶどう果汁以外を持つ人に命中 | +076 |
| 1 人以上いて，全員が適合飲料のときの乾杯（0.1 秒ごと） | +237 |
| 適合しない人がいるときの乾杯（0.1 秒ごと） | −0167 |
| ふらのワインかふらのぶどう果汁を持つ人に命中 | −38 |

0167 と 076 は値の元ネタに合わせ，先頭の 0 を付けて書く．計算では 167 と 76 として扱う．

表 2 は端末ごとの操作である．

表 2. 端末ごとの操作．

| 操作 | スマートフォン | PC |

| 乾杯する | 乾杯ボタンを長押し | Space キーを長押し，またはボタンをマウスで長押し |

## ⚠ 注記

ゲームの画面には，要件書の文案どおり次の注記を載せている．

> 非公式のファンゲームです。富良野市、富良野市ぶどう果樹研究所、コンシェルジュ フラノとは関係ありません。
>
> 実際の条例は努力義務で、罰則はありません。飲み物は自由に選んでください。
>
> 20歳未満の飲酒は法律で禁止されています。ぶどう果汁でも乾杯できます。
>
> 雪合戦以外で、雪玉を人にぶつけないでください。

あわせて，次の点を記しておく．

- 題材の「富良野市まずはふらのワインで乾杯条例」は実在する．雪玉で退場させるルールはゲーム上の誇張表現である
- 会場は TechRAMEN 2026 Conference の会場（コンシェルジュ フラノ 1 階）をモチーフにした
- 現在の版は，ゲーム自体では利用者の情報を保存せず，アクセス解析も使わない
- 配信元の GitHub Pages は，セキュリティのために閲覧者の IP アドレスを記録する

条例の原文は富良野市の例規集で読める．

- [富良野市まずはふらのワインで乾杯条例](https://en3-jg.d1-law.com/furano/d1w_reiki/H425901010029/H425901010029.html)

## 🛠 開発の進め方

- Claude Code で開発し，テストファーストの TDD で進める
- Pull Request は Draft で作成する
- 着手の手順は `docs/requirements.md` の「Claude Code への依頼文」の章を参照する
- 技術構成は TypeScript，Vite，Canvas 2D，Vitest，Playwright である
- 構成の選定理由は `docs/notes/2026-11-25-tech-stack-and-complexity.md` に記録した

表 5 は開発で使うコマンドである．Node.js は `.node-version` の版を使う．

表 5. 開発で使うコマンド．

| コマンド | 内容 |
|---|---|
| `npm ci` | 依存を入れる |
| `npm run dev` | 開発サーバーを起動する |
| `npm run build` | 型を検査し，公開用のファイルを `dist/` に作る |
| `npm run preview` | `dist/` を手元で配信する |
| `npm test` | 単体テストを実行する |
| `npm run test:e2e` | E2E テストと axe-core の検査を実行する |
| `npm run lint` | ESLint で静的解析する |
| `npm run typecheck` | TypeScript の型を検査する |
| `npm run complexity` | `cccc` で関数ごとの複雑度を測る |
| `npm run og-image` | OGP 画像を `assets/og-image.svg` から作り直す |

- E2E テストの初回は `npx playwright install chromium` でブラウザを入れる
- Content Security Policy はビルド時だけ付く．確かめるときは `npm run dev` ではなく `build` と `preview` を使う
- `npm run og-image` は Playwright の Chromium で SVG を描く．日本語の題字は手元の日本語フォントで描かれるため，作り直したら PNG を目で確かめる
- OGP 画像は半分の大きさで描き，点描（組織的ディザ）でウェブセーフカラーに丸めてから 2 倍に拡大する．ドットの見える昔の画像に見せるためである
- `cccc` は `moznion/cccc` の v1.10.0 を PATH に置く．環境変数 `CCCC_BIN` でも場所を指せる
- 複雑度の上限は cognitive と cyclomatic ともに 8 で，`cccc.toml` に書いた

- デプロイの job の権限は `pages: write` と `id-token: write` だけとする
